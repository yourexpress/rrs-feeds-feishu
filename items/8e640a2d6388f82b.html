Make Every Expansion Count: Learning to Search Efficiently in LLM Code Repair

arXiv · 2026-10-14 · 论文PDF

研究问题：LLM 代码修复系统反复生成并测试修订，每次都很昂贵——如何决定先尝试哪个修复以提升效率？

方法：提出 CodeTriage 学习策略：0.6B 参数模型读取测试输出、失败诊断与提议编辑，预测沿该编辑达到修复所需的步数分布，在生成测试前对所有待处理编辑排序；另发布含 4 个 LLM、组织成修复树的 1,220 万程序版本语料。

关键数字：在保留任务上比最强基线少 21% 的程序修订、少 12% 输出 token；无需重训即可在 11 个未见修复 LLM 的搜索预算上取得最高平均成功率；消融显示失败上下文、编辑文本与跨程序比较都有贡献。

为什么值得看：把「先修哪个」变成可学习问题，跨模型泛化强，代码修复管线可直接受益。
