Five developer takeaways from Arm Create for building and deploying AI

A capable model is only the starting point. Building an AI application means deciding what sits around that model as latency, cost, privacy, power, and deployment targets begin shaping the design.

At Arm Create 2026 in Shanghai and Shenzhen, developers explored those decisions across cloud, edge, mobile, graphics, and physical AI through keynotes, partner discussions, technical deep-dives, and hands-on labs.

Arm’s latest hardware and software announcements were part of those discussions. Arm AGI CPU and Neoverse CSS N4 expand cloud infrastructure options, Arm CSS for Mobile 2 supports new mobile on-device AI experiences, and Arm Mali G2-Ultra NX brings neural capabilities to mobile. Meanwhile, the new Arm AI Portal helps developers discover models validated and optimized for Arm-based platforms, understand the target fit, and find code and deployment workflows.

However, the useful question for developers is not simply what each platform or tool does, but what they help them make decisions, experiment and test, and improve their software.

The Arm Create Shanghai keynote framed the challenge into four questions:

- Which intelligence fits the task;

- Where the work belongs;

- How the pieces work together as a system; and

- Whether the application performs as intended on its real target.

The sessions and labs turned those questions into five key developer takeaways.

1. Decide what infrastructure an agentic application needs

When an application becomes agentic, the model is only one part of the challenge. Agents can generate code, call tools, and take actions dynamically, placing new demands on the infrastructure underneath them.
