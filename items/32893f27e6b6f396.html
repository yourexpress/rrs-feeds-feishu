Weight Placement Is Not Enough: Synchronization in Multi-Node CPU Decoding of Ternary LLMs

arXiv · 2026-10-20 · 论文PDF / 每日精选

研究问题 三值 LLM 每解码 token 只读几 GB，但四 NUMA 节点双路服务器上最快三值运行时只用不到一半内存带宽——把权重放在读取它的线程所在节点就够了吗？

方法 构建节点局部权重、复用 ik_llama kernel 的解码引擎，用逐线程 barrier 追踪定位等待来源；比较 Megatron 风格列切分与行切分（无跨节点归约），并隔离 barrier 数量效应。

关键数字 两代 Xeon 上线程每 token 有 20–48% 时间等在同步点，主要是等各节点最慢线程；列切分在全部配置下胜出；DRAM 受限解码较 ik_llama 全核快 1.5–2.1×、较其最快线程数 1.5–1.9×（L3 缓存小模型 3.2×/2.8×），同精度且每 token 能耗更低。

为什么值得看 指出多节点 CPU 三值解码的真正瓶颈在同步而非带宽，给出可复现的列切分工程答案。
