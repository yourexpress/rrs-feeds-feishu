Lightweight Scheduling Policies for Continuously Batched LLM Serving Across GPU Architectures

arXiv · 2026-10-14 · 论文PDF / 每日精选

研究问题：连续批处理（continuous batching）下自回归解码的调度日益成为瓶颈，轻量调度策略能否不改模型、内核或上学习式调度器就改善时延-吞吐权衡？

方法：实现 Python/PyTorch 连续批处理测试台（真实 Hugging Face 执行），以 ShareGPT 派生流量、6 个 Qwen/Gemma/Mistral 模型、L40S/A100/H100 GPU 共 1152 次运行评测 8 种策略。

关键数字：固定模型、GPU、负载、批大小与 prefill 预算下，调度器选择显著改变吞吐、TTFT、完成时延与尾部行为；"aging + 最短 prompt 优先"在多数 L40S 与混合负载场景是最强实用基线，而 oracle 剩余长度调度表明仅知道任务长度并不够。

为什么值得看：为 LLM serving 调度提供大规模可控实证与可直接部署的实用基线。
