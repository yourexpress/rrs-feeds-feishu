The Rounding Error That Stops the Machine

DEV Community（AI 生成） · 2026-10-12 · 技术博客

核心话题 LLM 服务中 CPU 侧 tokenizer 从"可忽略的舍入误差"变成吞吐瓶颈的综述性评述。

要点 当 GPU 推理足够快、并发请求多或长输入反复处理时，tokenizer 成为前置瓶颈：SGLang/vLLM 的 tokenizer 虽用 Rust/C++ 实现，但每次调用都穿过 Python 的 GIL 全局锁，形成单文件队列；agent 长历史每轮全量重 tokenize 而 GPU 侧大量缓存命中，CPU 步长相对膨胀。

关键数字 Georgia Tech 研究：充足 CPU 分配下，首 token 等待时间在各配置中下降 1.47–7.11 倍；HF 重建 tokenizer 编码路径单线程较 v0.23 快 3–30 倍，8 worker 下以线性 76% 扩展。

为什么值得看 汇总 HF Tokenizers v1、PyTorch SMG 与 Georgia Tech 三源，指出 tokenizer 瓶颈的测量与解法分歧（多核 vs 移出 Python），对 LLM 服务调优有参考价值。
