Taking Tokenization off the Host for Agentic LLM Serving

arXiv · 2026-10-09 · 论文PDF / 每日精选

研究问题：Agent 负载反复发送几乎不变的长上下文，前缀缓存跳过了 prefill，但每个请求仍要完整分词才能查缓存——分词这个「可忽略的 CPU 阶段」成了 TTFT 最大头，还限制一个前端能喂多少 GPU。 方法：GraphTok 把从预分词、BPE 合并到 token-ID 组装的整条编码管线做成一个可重放的 CUDA 图；短输入回落 CPU 引擎；比特级复现 GPT-2/Llama 3/Qwen 2.5/DeepSeek-V3/Gemma 3 的参考 token ID，即插即用 vLLM 与 NVIDIA Dynamo。 关键数字：100 万 GPT-2 token 编码 1.7~3.2 ms（含传输）；Llama 3 上比最强 CPU 分词器 gigatoken 快 4.7~6.0×；缓存前缀下 vLLM 平均 TTFT 降 2.1~2.4×；2 秒 P99 目标下单前端 518 请求/秒（121k token 流量），约为 gigatoken 的 1.75~2.5×。 为什么值得看：盯住了 agent 时代服务栈里最反直觉的新瓶颈，工程完整性（位级一致、可插拔）是范本级。
