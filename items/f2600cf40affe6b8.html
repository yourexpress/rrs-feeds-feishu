One Structure Is Enough: Record-Native Tiles for Evolving Sparse Matrices on GPUs

arXiv · 2026-11-23 · 论文PDF / 每日精选

研究问题：随时间演进的稀疏矩阵（如流式图）在 GPU 上通常用打包格式（CSR/ELL/SELL）计算 + 独立缓冲更新，定期维护合并/重建/换格式——这种分裂是否必要？

方法：RecTile 分片存储层：每片保持在一个 12 字节边记录的有序数组；全 GPU 摄取流水线处理插入/删除/修改批；精确动态规划 oracle 在动作空间与标定成本模型下决策折叠。

关键数字：碎片矩阵（每片 1-21 非零）下与最优 format-pinned slab 片时间比 0.56-1.21x；分片布局比整矩阵 cuSPARSE CSR 快最多 21x；摄取流水线最高 2900 万边/秒、比 host 路径快 4.5x；标准折叠启发式用 4-15x GPU 时间、最多 4x 持久存储；5 个演进图工作负载时间-存储权衡全部改善。

为什么值得看：挑战"计算格式+更新缓冲"二分范式，单一可变记录结构 + 全 GPU 摄取。
