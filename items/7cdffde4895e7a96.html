LazyWeights: Decode-on-Demand Edge LLMs

arXiv cs.LG · 2026-11-12 · 论文PDF / 每日精选

研究问题：边缘设备内存决定能跑什么 LLM 与多快（4GB Nano 容量受限、8GB Orin Nano Super 带宽受限）；GPTQ/AWQ/K-/I-quants 对矩阵每个整数码花费等量比特，但码并不均匀。

方法：LazyWeights 保留现有格式但调整 GPTQ 使码可压缩，Huffman 无损编码交错 lane，DRAM 与 L2 间小单元按需解码；GPU kernel 不变，DRAM 只移动编码字节。

关键数字：1%/3.5% perplexity 预算下 Phi-3-mini/Mistral-7B/SmolLM-1.7B 比最佳 llama.cpp 格式小 5.7-31.4%；0.21mm² ASIC 解码器（1GHz, 7nm）削减 Orin 每 token 延迟/能耗最多 36%/38%（prompt-lookup 投机下 54%/44%）；Nano 上比 CPU llama.cpp 每 token 少 58-64% 时间、53-57% 能耗，流式 Mistral-7B 快 6.6x @ 3.89 bits/weight。

为什么值得看：边缘 LLM 内存优化的端到端方案，格式兼容 + 专用解码硬件。
