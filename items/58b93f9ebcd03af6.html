AscSpMM: Efficient SpMM on Ascend NPUs via Pipelined Vector-Cube Collaboration

arXiv cs.AR · 2026-11-09 · 论文PDF / 每日精选

研究问题 NPU 矩阵引擎与软件管理片上内存偏好稠密计算，而 SpMM（图分析、稀疏神经网络、科学计算关键内核）需要索引驱动操作数选择、间接寻址、分散访存与负载均衡，与 NPU 固定形状/连续布局冲突；GPU Tensor Core 方法无法直接迁移到向量/矩阵引擎解耦的 NPU。

方法 提出 AscSpMM：用参数化 Vector-CSR 表示把不规则操作数准备与规则矩阵计算分离——向量引擎解码索引、收集重排稠密操作数，Cube 引擎做矩阵乘累加；双槽环形缓冲实现依赖感知异步流水，操作数复用与运行时自适应分块减少跨引擎停顿。

关键数字 Ascend 910B3 上相对 GEMM 几何平均加速 2.36x、相对既有 SpMM 实现 19.92x、相对 A100 上 cuSPARSE 5.82x；矩阵输入存储与峰值 HBM 占用平均降 48.24% 与 22.98%，与专用 GPU Tensor Core SpMM 内核竞争力相当。

为什么值得看 NPU 上 SpMM 的向量-矩阵引擎协同设计范式，含异步流水与访存优化细节，代码已开源。
