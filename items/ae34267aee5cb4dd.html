GLM-5.3 Optimizations, Part 2: PCP, DCP, and Hybrid HiSparse on 16 H200s

vLLM Blog · 2026-10-23 · 技术博客 / 每日精选

核心话题 GLM-5.3 长上下文 agentic 场景在 H200 上同时撞上两个瓶颈——KV cache 内存与 prefill 速度；第二篇优化日志给出 16 张 H200（1 prefill 节点 + 1 decode 节点）上的解法组合。

要点 PCP（Prefill Context Parallelism）按 token 而非按 head 切分 prompt，适配 GLM-5.3 稀疏注意力；DCP（Decode Context Parallelism）按 token 切分 prefill 引擎的 KV cache，消除 MLA 下每 rank 全量复制；Hybrid HiSparse 让 decode 侧把 KV 放主机内存，1M token 请求可整体放下；对比了 DP8/TP8 为何不行（DP 无法跨 GPU 分摊长 prompt 注意力，TP 让 MLA 潜在 KV 被 64 头共享、每 GPU 全量存储只服务 8 头）。

关键数字 AgentX 上 PCP8×DCP8 prefill + Hybrid HiSparse decode 相比数据并行部署，单用户速度提升 1.7–3.2×；是唯一实测能服务 1M token 上下文的配置。

为什么值得看 长上下文 + 稀疏注意力 + P/D 分离的工程组合题，vLLM 官方给出可复现的拆解路径。
