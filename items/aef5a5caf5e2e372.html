Speculative Decoding for Mixture-of-Experts Models: Expert Bytes, Kernel Bandwidth and the Best Draft Length

arXiv(cs.LG) · 2026-10-25 · 论文PDF / 每日精选

研究问题 MoE 投机解码中连续 token 常选同一批专家，去重引擎每 pass 每专家只读一次、请求字节更少，但它在什么条件下真的更快？

方法 把一步时间写成各 kernel 请求字节/有效带宽加固定时间，几何接受假设下推导投机快于普通解码的条件，最优草稿长度为接受率的单调阶梯；在 llama.cpp Metal、MLX-LM 与 llama.cpp CUDA 上实测（已改造支持去重）。

关键数字 per-slot kernel 有效带宽更高（r=0.32 到 0.75），去重仅每 pass 5-8 token 或从不更快；实测节省落在误差界内：CUDA/MLX-LM 全部点、Metal 48 点中 36 点；DeepSeek-V2-Lite 上 CUDA 最优草稿长度在 22 个接受率上全部命中（±1 内）。

为什么值得看 把 MoE 投机解码的字节/带宽账算清楚，直接指导草稿长度与去重取舍。
