PACE: Keeping the Right Tokens in the KV Cache Is Not Enough for Long-Horizon LLM Agents

arXiv cs.LG · 2026-11-06 · 论文PDF / 每日精选

研究问题 长程 LLM agent 会话可达百万 token 级 KV cache，远超单 GPU 容量；现有驱逐方法只保证「需要的 token 还在缓存里」，但 token 在位不等于可取回。

方法 提出 PACE（Planner-Aware Context Engine）：① 计划感知保留——由 agent 的 planner 告知缓存未来步骤将读取哪些上下文；② 有界位置重编号——重排保留 token 使其旋转位置距离在任意会话长度下低于 8K。

关键数字 100K token 会话、2,048 token 预算下，保留 99%+ 所需 token 的策略准确率仍从 93% 跌至 64%；PACE 通过 97% 隐藏单元测试（H2O 42%、SnapKV 3%）；1M/2M token 会话在单张 24GB GPU 上通过 99%/100% 检查，KV 占用 <0.7GB（全量需 147–295GB），仅增 9% 墙钟时间。

为什么值得看 指出「保留正确 token」之外的第二个瓶颈——位置距离可取回性，并给出无需重读历史的工程解法。
