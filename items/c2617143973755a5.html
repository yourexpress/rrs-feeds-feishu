LeanSparse: Memory-Efficient Serving for Native Sparse-Attention LLMs

arXiv (cs.DC) · 2026-11-03 · 论文PDF / 每日精选

研究问题 稀疏注意力限制了每个 query 读的历史，但长上下文服务仍占用大量 GPU 内存：现有 KV offloading 系统在 GPU 上保留完整 indexer key 历史，限制 decode 并发；prefill 的临时内存需求还会在内存本够用时延迟请求准入。

方法 提出 LeanSparse（SGLang 实现）：利用两个观察——prefill 逐层消费历史数据、decode 可在比较原始 indexer 分数前先识别候选。prefill 阶段让层历史流经两个可复用 GPU 缓冲，与模型计算重叠；decode 阶段用粗到细索引搜索紧凑表示，仅对候选细化才取回原始 indexer key；indexer key 与 KV cache 分离并跨生成步复用。

关键数字 DeepSeek-V4-Flash、950K 上下文：并发请求数为 HiSparse 的 2.95x、decode 吞吐 2.14x；多轮 Open-SWE 轨迹上中位首 token 时间从 21.6s 降至 0.6s，中位会话完成时间相对 ECHO 降低 17.7%。

为什么值得看 同时压 decode 持久内存与 prefill 临时内存两块瓶颈，在 950K 超长上下文上取得近 3 倍并发提升，工程落地价值高。
