GC-MoE: Overlapping Expert-Parallel Token Dispatch with FP8/FP4 Grouped GEMM via CUDA Green Contexts

arXiv (cs.DC) · 2026-11-03 · 论文PDF / 每日精选

研究问题 专家并行（EP）下 MoE 每层都要做 all-to-all token dispatch、grouped GEMM 与 combine；decode 时每 rank 仅 1-256 token，dispatch 延迟与权重流量主导、张量核利用率天然很低。现有融合算子（如 DeepGEMM Mega MoE）让 dispatch 与计算共享每个 SM 的资源预算与同步域，互相争抢。

方法 提出开源 GC-MoE（NVIDIA Hopper/Blackwell 的 FP8/FP4 MoE 推理算子）：用 CUDA Green Contexts 把设备分成小的通信分区与大计算分区，各自拥有独立内核、资源预算与同步域；三节点 CUDA Graph（Hopper 上加融合共享专家为四节点）并发启动 dispatch 与 grouped-GEMM，token-ring 握手在首批 ring 块填满时即开始计算，双缓冲接收计数器去掉 replay 间尾部跨 rank barrier。

关键数字 8x H20 上 DeepSeek-V4.1-Flash decode 平均加速 1.188x（峰值 1.296x/1.353x）；8x B300 上 GLM-5.2 与 DeepSeek-V4.1-Flash 加速 1.106x（融合共享专家 1.123x，峰值 1.209x），54 个测量点全部超过 Mega MoE。

为什么值得看 用 Green Context 硬件机制从根上隔离 dispatch 与计算资源，公开开源，是 MoE decode 推理算子优化的新范式。
