Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read It

arXiv（Yipeng Liu 等，cs.DC） · 2026-09-16 · 论文PDF

研究问题 Agentic 请求的墙钟时间大量消耗在等待工具上，期间 KV 缓存一直占着 GPU 显存；服务系统决定缓存去留时只能"猜"工具耗时——靠工具名、历史、调用前声明或引擎占用，但任何调用前固定的估计都无法预知时长，甚至连排序都可能排错。

方法 主张工具在运行时显式上报进度，并实测其可行性：对四个公开 agent 语料的普查发现多数工具时间里存在可读信号（剩余工作比例或"临近结束"信号）；一个 harness 可在不改变 agent 所见、不损基准分数的前提下恢复该信号；通过少量 hint 接入生产引擎做 KV 缓存决策。

关键数字 上报进度的准确度比已发表最优预测器高数倍到一个数量级，且环境变化时仍保持准确；工具调用后 p90 TTFT 相比 LRU 降低 20.7%（仅 HBM）和 20.8%（HBM+DRAM），接近 oracle。

为什么值得看 "别猜，问工具要进度"的理念简单却有力，为 agent 服务的显存调度指出了一条被忽视的工程路径。
