Don't Let the Model Write the YAML: Deterministic, Minimal-Diff GitOps Remediation from LLM-Proposed Field Changes

arXiv（Pruthvi Davineni，cs.SE） · 2026-08-31 · 论文PDF

研究问题 LLM 智能体诊断事故后要改 GitOps 里的版本化配置文件，直觉做法是让模型直接产出 diff 或整文件重写——这在无人值守自动化下安全吗？

方法 在真实 Kubernetes manifests 上评测后给出替代方案：语义决策（改哪个资源/字段/值）与语法编辑分离。Agent 只输出结构化字段变更意图；确定性管线按 (kind, name) 索引、借 YAML parser 的节点位置标记定位标量精确字符区间，只替换该区间——文件不重新序列化，diff 天然最小、格式注释保留、结果与模型无关且确定，生成成本 O(1)。已实现于 KubeAstra（Apache-2.0）并发布基准。

关键数字 unified diff 用 GNU patch 容错应用可达 96%，但其中约 1/7（14%~20%）被静默错打且无错误信号；整文件重写前沿模型仍有非确定性地丢字段/改邻近字段的问题。

为什么值得看 「LLM 出意图、确定性代码动手」的 fail-closed 契约是 Agent 落地运维的通用范式，评测结论对任何让模型改配置的系统都是警示。
