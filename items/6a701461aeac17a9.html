NVIDIA DSX AI Factory：AICR v1.2.0 + Kubernetes AIBOM（application bill-of-materials）实现运行时 AI 库存验证——启动前用 SBOM 工件校验驱动/固件/库版本匹配 GPU 平台，fail-fast 快速定位不兼容，面向 AI 数据中心规模化部署验证

As teams deploy and scale AI workloads using NVIDIA Dynamo, Kubeflow, or Slurm, tracking what actually runs requires visibility beyond the platform configuration captured in a recipe. Application teams define and update these workloads independently of the platform recipe, so a reproducible deployment bundle alone cannot establish which workload artifacts are running on each node. Mutable image tags like :latest

add another layer of complexity. Two nodes can end up running different code under identical tags, and a node that pulls next week may retrieve an image that was not covered by an earlier security review.

NVIDIA AI Cluster Runtime (AICR), an open source modular component of the NVIDIA DSX AI Factory Platform, now includes a qualified AI bill of materials (AIBOM) component to close that gap. An open source project created by Google, k8s-aibom tracks AI workloads running on Kubernetes. Two stock recipes select k8s-aibom by default: h100-gke-cos-inference

and h100-gke-cos-inference-dynamo

. Other GKE recipes can opt in during generation with --runtime-inventory

enabled. Recipes selecting it can opt out with --runtime-inventory

disabled.

AICR turns known-good GPU platform configurations into version-locked recipes and reproducible deployment bundles. Each recipe records the desired configuration for one hardware, cloud, OS, and intent combination: its components, version pins, values, constraints, deployment ordering, and validation expectations. AICR generates reproducible deployment artifacts from fixed recipe, catalog, and bundle inputs. Bundles include checksums; signing is optional through aicr bundle --attest

.
