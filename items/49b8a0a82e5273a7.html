EfficientAgent: What Makes KV Cache Offloading Work for Concurrent Agents?

arXiv (cs.DC) · 2026-09-27 · 论文PDF

研究问题： LLM 智能体每轮重发整段对话，服务系统靠 KV 缓存避免重算，GPU 内存不足时卸载到主机内存；但同一编码智能体负载下，卸载在一个部署中加速、在另一个中减速、在第三个中毫无变化——卸载何时才真正生效？ 方法： 关键洞察是缓存必须存活到再次被用：一个智能体等工具时服务器在处理其他智能体上下文，只有主机层持有整个智能体池的可复用上下文（复用工作集）时 prefix 才会被复用。EfficientAgent 用 stack-distance 模型从智能体历史估计工作集来配置主机层；层过小时运行时策略停止写被驱逐的大 refill、只扩展仍在缓存的 prefix，层够大时全写。 关键数字： SWE-bench Verified 上按估计工作集配置主机层，重算 prompt token 减 93%、端到端时间减 39%；小固定层减 35% 重算；大层避免始终过滤写入带来的 4.3 倍增长。 为什么值得看： 给出"卸载何时划算"的可解释判据与可落地的容量规划方法。 原文链接：EfficientAgent: What Makes KV Cache Offloading Work for Concurrent Agents?
