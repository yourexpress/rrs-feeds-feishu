Opportunistic ZGC: Leveraging Idle Cores for More Effective Concurrent Garbage Collection

arXiv（Jacob Malloy 等，cs.PL） · 2026-09-14 · 论文PDF

研究问题 ZGC 虽能并发回收、停顿低于毫秒，但默认调度保守——堆长快满才回收；若最大堆配置不当，既浪费内存又可能损害延迟敏感应用，且逐应用调参成本高。

方法 提出 Opportunistic ZGC（OppZGC）：反馈驱动的调度策略，识别 CPU 空闲时段并趁机执行并发回收，动态自动约束堆大小；当额外回收会明显损害性能时则不加收。已在 OpenJDK HotSpot 实现。

关键数字 在 DaCapo Chopin 与 SPECjbb 上，DaCapo 基准最大堆用量按配置平均降低 61%~90%，吞吐与请求延迟影响极小。

为什么值得看 "用空闲核换内存"的思路简单有效且已进入生产级 JVM 语境，大内存 Java 服务可直接受益。
