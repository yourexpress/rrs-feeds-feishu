Agent Substrate: Advancing Kubernetes for Agents at Scale

NVIDIA Technical Blog · 2026-11-10 · 技术博客

面向 agent 负载的 Kubernetes 调度改造（agent 大部分时间空闲等待），超出 24h 检索窗口且偏数据中心调度，不入选

AI agents spend most of their time idle, waiting on a human prompt, a tool result or a model response. Kubernetes wasn’t built for that. Running one Pod per session holds memory for sessions that aren’t doing anything, and deleting Pods between turns pays a multi-second cold start every time and loses the agent’s state. RL post-training hits the same wall.

Agent Substrate, now donated to the Cloud Native Computing Foundation (CNCF) Sandbox, is an open-source, security-hardened, zero-trust runtime for sandboxed agents, engineered to safely run millions of agents and tools with 10x higher density than standard containers. It multiplexes many sessions over a small pool of worker Pods. Idle sessions are checkpointed, memory and filesystem included, and restored onto whichever worker is free when the next request arrives. As agentic infrastructure fragments into proprietary runtimes that bypass Kubernetes, NVIDIA is contributing upstream to keep this work open.

This post covers which workloads suit Agent Substrate, what is being built upstream, and how the project works with KAI Scheduler and NVIDIA Dynamo components in the DSX AI Factory Platform.

The shape of an agent workload

Traditional web services run as a relatively small number of long-lived instances. Agents follow a different pattern: they wake up and take one step, running a shell command, editing a file, calling a test suite or calling an LLM. Then they wait, sometimes for milliseconds and sometimes for minutes, before the next step. The agent’s state (its filesystem, its processes, its working directory) has to continue between steps.

Kubernetes struggles because spinning up a compute Pod for an agent means a trip through the API server, admission, etcd, the scheduler, the kubelet, image pulls and network setup. That takes seconds, which is fine for a service that runs for weeks. It’s far too slow for a sandbox that must appear, run a 10 ms bash command and get out of the way, hundreds of times per second.
