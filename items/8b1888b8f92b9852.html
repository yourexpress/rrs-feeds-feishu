No-Restart Elasticity in an Adaptive Runtime System for Cloud-Native HPC

arXiv (cs.DC) · 2026-09-26 · 论文PDF

研究问题 用折扣 spot 实例跑 HPC 需在运行时改变资源分配（中断前收缩、扩容补位），但现有弹性机制按"完整进程拆除+冷重启"实现——重启阶段占总开销最高 95%，且随节点数与 GPU（CUDA 上下文初始化）增长。

方法 为 Charm++ 运行时提出无重启缩放机制：存活性进程永不退出；缩放操作 = 与轻量外部协调器做成员协商 + 按新集群视图对账 UCX 通信端点 + 回到保留活动应用状态的运行时初始化路径顶部；进程存活使 GPU 设备状态原地保留，取消 GPU 弹性所需的 checkpoint 守护进程，去启动器引导机制摆脱与 spot 中断不兼容的受管进程。

关键数字 缩放成本（不含负载均衡）在 4–32 实例上从数秒降到 CPU 8–15ms、GPU 7–11ms；8 次同时中断的端到端开销降到 CPU 0.2%、GPU 0.6% 运行时间；1% 开销以下可缩放速率提高 7 倍。

为什么值得看 无重启弹性是 spot 实例跑 HPC 的关键工程突破，对云原生高性能计算有直接价值。
