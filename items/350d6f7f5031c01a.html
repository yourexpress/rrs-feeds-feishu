Fast Recovery for LLM Serving via Decoupled Device Memory Lifetime in Dynamo

arXiv (cs.DC) · 2026-09-23 · 论文PDF / 每日精选

研究问题：LLM 推理副本连跑数周，单个 worker 故障就会打断整个副本；即便权重与编译产物已缓存，引擎重新初始化仍需数分钟——生产环境只能靠超配容量掩盖这个窗口。

方法：NVIDIA Dynamo 快速恢复：核心观察是 18 周集群故障分析显示多数故障"保留设备"——引擎进程挂了但 GPU 及驻留分配完好。快照捕获一次初始化引擎、之后恢复而非重建；GPU Memory Service（GMS）把设备内存所有权与引擎进程解耦，替换引擎可共享并重挂存活分配而无需拷贝，权重只读共享给替换与 Shadow Engine，恢复退化为一次"提升"。

关键数字：vLLM 与 SGLang 上 4 个模型恢复均在 7 秒内，比热重启快 13–29×；每 GPU 固定 4–8 GiB 显存开销（与模型大小无关）；回放生产 trace 估计可挽回 79% 因恢复损失的 GPU 时。

为什么值得看：把 serving 可用性工程化的代表作，"保住已初始化的引擎状态"这个视角对任何长时推理服务都适用。
