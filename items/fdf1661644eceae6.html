PhaseGate: Phase-Aware CPU Retrieval Scheduling for On-Device LLMs on Unified Memory

arXiv cs.LG · 2026-10-06 · 论文PDF / 每日精选

研究问题 统一内存系统上，端侧助手让 GPU 跑 LLM 推理、CPU 跑本地检索并发进行——CPU 检索会如何干扰 LLM 延迟、该用什么信号做准入控制？

方法 先量化干扰：两台 M4 系统上四个并发检索 worker 使 p95 解码延迟上升 60–61%，而 prefill 仅升 5.7–6.9%。据此 PhaseGate 以 LLM 相位为准入信号，为 prefill 与 decode 分别校准并发上限（基础 M4 上取 4 与 1）。对照组 TimeGate 用相同两档限额但按校准时间表切换、不观测相位。

关键数字 积压队列下 PhaseGate 检索总吞吐达最优可行固定策略的 2.0 倍，七次留出运行中两项 p95 LLM 延迟均在无检索基线的 1.25 倍以内；TimeGate 吞吐相近但每次运行都违反输出 token 延迟约束；M2/M2 Pro 复现该策略排序。

为什么值得看 "相位感知准入"简单有效且可复现，对统一内存端侧部署（Apple Silicon 类）的 LLM+RAG 混合负载是现成的调度策略。
