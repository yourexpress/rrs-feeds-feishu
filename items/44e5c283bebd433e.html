Decomposing Predictive Kubernetes Autoscaling for Large Language Model Serving Under Long Startup Delays

arXiv（Tianrui Liu 等，cs.PF/cs.DC） · 2026-09-16 · 论文PDF

研究问题 Kubernetes 上的 LLM 推理面临常规 Web 服务没有的扩缩难题：新副本要加载数 GB 权重、启动需 2~10 分钟，纯反应式扩缩结构性滞后。预测式自动扩缩器的各组件中，到底哪些真正起作用？

方法 把预测式扩缩分解为四个因子——token 感知需求跟踪、启动延迟前瞻、有界不确定余量、装置状态观测——在 ServeGen 生成的生产重尾负载上逐一隔离测量贡献；并在真实 K8s 集群（Qwen2.5-7B + A100 + vLLM）上验证。

关键数字 简单 EWMA 预测器加延迟前瞻与 UCB 余量即可拿下大部分收益：TTFT SLO 违规率从 53% 降到 0.5%（5 个随机种子）；仅前瞻一项就带来 14 倍降幅；真实集群上延迟感知前瞻控制器把 TTFT 违规从 63.5% 降到 3.7%；Kalman 变体无一致改进。

为什么值得看 罕见的「拆因子归因工作」，结论直接可用：token 粒度与延迟前瞻是必须项，复杂滤波器未必值得。
