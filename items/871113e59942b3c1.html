Placing the Control Plane: Cloud-Native Federated Learning Across Batch-Scheduled HPC

arXiv · 2026-11-23 · 论文PDF

The United Kingdom's AI Research Resource (AIRR) opens national supercomputers to a community familiar with always-reachable cloud services. With batch-scheduled HPC, a user requests a time-bounded allocation that is then reclaimed. Federated Learning (FL) exposes this tension, pairing a long-lived control plane with short-lived training. We characterize the resulting placement asymmetry: the coordination server sees only model updates and control metadata, so it can sit on neutral infrastructure, whereas the client control process is bound to the participating site's data and must remain within its trust boundary. The outbound-only connection this implies is also how edge clients connect, though the batch-scheduler mismatch is specific to HPC. We demonstrate a cross-silo federation spanning three independently administered systems (Isambard-AI, Isambard 3, and Zenith) using unmodified production FL frameworks (FLARE-wrapped Flower), measure the cost the client placement incurs, and propose Kubernetes-as-a-service as the in-boundary home for the persistent process.
