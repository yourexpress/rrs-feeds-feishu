Working Around the Compute Ceiling: Byte-Exact Memory in Galahad Makes LLM Reading a One-Time Cost LLM Reading a One-Time Cost

arXiv / Sietse Schelpe 等 · 2026-09-30 · 论文PDF

研究问题 transformer 每 token 计算量有界，而服务是无状态的：回答关于同一文档的第二个问题时，模型会从头重算文档的注意力状态，浪费计算预算。

方法 提出 Galahad 内存层（适配 vLLM/SGLang/llama.cpp）：Taliesin 保存文本块的 KV 状态、下次遇到相同字节直接加载；Blaise 保留文档本体、只把问题所需章节喂给模型；恢复状态位级一致，加载校验不过则回退重算。

关键数字 7 个真实数据集上 98.7% 的 prompt token 是模型已读文本；97k token 语料 100 事实召回测试（Gemma 4 31B）：Taliesin 单独 98/100（3.0s、572J）对比无 Galahad 10/100（9.3s、2754J）；加 Blaise 后 100/100（0.59-0.64s、200-213J），而调优 RAGFlow 仅 77；262,144 个输出 logits 重启后全部位级匹配。

为什么值得看 把 LLM 服务从无状态推向有状态，同时给出能耗与延迟的实测收益。
