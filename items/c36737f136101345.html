Pipeline-Native Transformers: Co-Designing Model Architecture and CPU Inference for Bandwidth-Efficient Autoregressive Decode

arXiv（Tom Poperszky，cs.AR） · 2026-08-24 · 论文PDF

研究问题：CPU 上单 token 自回归解码被内存带宽卡死（约 1 TFLOP/s 算力对约 50 GB/s 带宽），架构与推理运行时能否协同设计来省带宽？

方法：提出 CPU 优先的流式引擎 cflow 与一族"流水线原生"Transformer 架构：层间依赖图按纵向 stage-major 调度构造，权重按计算消费顺序存为 L2 大小 tile，MoE 层只读 top-k 专家，投影融合，支持磁盘常驻专家的异步 I/O 重叠。

关键数字：TinyStories 上五个架构之一关键路径权重带宽降 2.00 倍（9.00→4.50 MB/token），困惑度仅差 0.24；tile 布局 L1 读缺失少 7.29 倍；30.9B 参数 MoE 在 32 核 Ice Lake 上解码 5.94 token/s，优于 llama.cpp 的 4.75 与 vLLM CPU 的 1.65；磁盘专家重叠再净赚最多 1.68 倍。

为什么值得看：罕见地坦承八条设计主张中一条被实测证伪、一条不确定；CPU 推理与模型架构协同设计的高质量工程报告。
