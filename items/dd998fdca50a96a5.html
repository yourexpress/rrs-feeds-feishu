Does Execution Require Target KV Fidelity? A Mixed-Fidelity KV Runtime for LLM Serving

arXiv (cs.LG) · 2026-09-27 · 论文PDF

研究问题： LLM 服务的 KV 缓存挤占 GPU 内存，而运行时通常只把配置的目标保真度表示当作可执行状态——内存压力下这种"唯目标保真度"契约会把 KV 短缺变成请求停滞与抢占。执行是否真的需要目标 KV 保真度？ 方法： 提出 ElasticKV 混合保真 KV 运行时：引入紧凑中间 KV 状态，让保真度成为运行时管理的执行属性；用成对结构布局把降保真转化为可复用 GPU 容量，双模式注意力后端直接消费紧凑状态同时保留原生目标路径，并按内存压力自适应管理保真度。 关键数字： 高并发下 TTFT 比 vLLM 低 3.8-4.0 倍、P90 TTFT 低 9.1 倍，生成质量保持不变。 为什么值得看： 把"保真度"从静态配置变成运行时管理属性，为内存压力下的稳定服务提供新思路。 原文链接：Does Execution Require Target KV Fidelity?
