Firepool: Brokering Warm GPU Capacity for Agentic and RL Workloads at LinkedIn

arXiv cs.DC · 2026-11-07 · 论文PDF / 每日精选

研究问题 AI agent 与 RL 训练器运行成千上万个短小的隔离 GPU 任务（工具调用、验证器、rollout），任务秒级完成但启动 GPU pod 需 20–35 秒甚至数分钟；热 pod 既要消除等待又不能浪费 GPU 或泄漏状态。

方法 Firepool（LinkedIn 的沙箱与执行经纪）：按硬件画像用共享基础镜像构建可互换 pod，任务开始时才绑定代码与依赖；仅把 pod 复用于上一个调用者、以分片 GPU 共享部署零 VRAM 待机 pod、用队列驱动预算限制热池 GPU 容量。

关键数字 峰值期 94.7% 的 3,206 个 pod 请求由热/待机容量服务；固定时长任务对比新 pod 每任务，agent 与 RL 循环分别快 13x 与 10.8x；热复用把 p90 启动延迟从 59.1s 降至 3.5s；待机晋升把切换等待从 51s 缩至 0.94s。

为什么值得看 生产级 warm-pool 经纪系统设计：可互换性、安全复用与容量成本三者如何同时满足。
