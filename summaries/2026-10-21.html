  • DuoPD：共享 HBM 的 GPU/近存计算混合架构（arXiv:2610.26131）：把轻量 PNM 单元集成进 HBM 逻辑层，让整个 decode 在近存侧执行，prefill 与 decode 并发时干扰极小，端到端吞吐最高达传统 PD 分离的 2.23 倍——给出了跳出 GPU SM 切分死结的架构答案。https://arxiv.org/abs/2610.26131
  • Ineffective Occupancy：异构 GPU 集群的就绪感知调度（arXiv:2610.25066）：在阿里 GPU 集群轨迹上发现即使容量充足且放置完成，仍有 52.70% 的执行记录从未就绪；只用九个准入时可见属性预测就绪概率，即可把无效占用从 43.64% 压到 27.15%。https://arxiv.org/abs/2610.25066
  • TideKV：分层分块 prefill 的延迟 KV 驱逐（arXiv:2610.24499）：只在层末统一驱逐、保住"看完完整 prompt 再选择"的性质，A100 上 64K 上下文构建期瞬时显存降 83.89%，RTX 4090 首 token 仅增 1.06% 并解锁 128K prefill。https://arxiv.org/abs/2610.24499
  • PlaneZip：PCIe swap 激活的无损 bit-plane 压缩（arXiv:2610.25033）：BF16 激活压 1.71 倍（零值压缩只有 1.18 倍），让"按完整传输时间计费"而几乎不 swap 的成本模型重新愿意 swap，重物化开销相对 MegTaiChi 降 73%/54%，预估引擎面积仅 0.036 mm²。https://arxiv.org/abs/2610.25033
  • SigmaTrace：库无关的 CPU/GPU 发起 RDMA 逐操作可观测（arXiv:2610.24328）：在 libibverbs/mlx5dv 层用内存插桩，首次无需改源码即可看到 GPU-initiated RDMA，主机侧开销 128 GPU 上 1.3%，并暴露出现有 profiler 看不见的 2.13 倍节点间流量倾斜。https://arxiv.org/abs/2610.24328
  • EdgeKernelBench：面向多边缘后端的 LLM kernel 生成基准（arXiv:2610.24648）：单次生成最好模型 Correct@1 达 64.5% 但 Fast@1.0 只有 25.5%，作者提出的分层 IR agent LEKA 把后者拉到 43.5%（同基座模型与预算下 Claude Code 为 26.1%）——"能跑通"远不等于"跑得快"。https://arxiv.org/abs/2610.24648
  • First-Order LoRA Training with Phone NPUs（arXiv:2610.24816）：把一阶 LoRA 训练中三处冻结权重乘法全部放到手机 NPU（推理时已驻留这些权重），训练图与 adapter 留在 CPU 并可后台断点运行，为端侧隐私微调给出最省资源的路径。https://arxiv.org/abs/2610.24816
  • SIXPPAC：12nm FinFET 混合信号流式 ML 引擎（arXiv:2610.26552）：全参数片上存储，0.8 V 下以 105 MS/s 处理 8b I/Q 基带样本、每次推理仅 4.18 nJ（0.42 POPS/W），是边缘常驻感知任务功耗基线的一组硬数字。https://arxiv.org/abs/2610.26552
